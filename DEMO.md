# 🎬 DEMO.md — сценарий и профиль для жюри ЛЦТ

Оперативный плейбук показа «Диалога». Код-фичи описаны в `CLAUDE.md`; здесь —
**как показывать**, чтобы главный дифференциатор (ИИ-судья, оценивающий *смысл*, а не
ключевые слова) был виден, а демо не сорвалось вживую.

> Главный риск (по аудиту): по умолчанию бэкенд стартует в `NEGO_AI=off`, а фронт
> молча падает в keyword-мок. Тогда жюри видит ровно тот keyword-классификатор,
> который весь проект и перерастал. **Судья должен быть включён и виден.**

---

## 1. Профиль показа (заблокировать и отрепетировать)

**Бэкенд — с живым судьёй, одинаковый источник (same-origin), без мок-фолбэка:**

```bash
# backend/.env (gitignored): ANTHROPIC_API_KEY=...  (или OPENAI_API_KEY для дешёвого пути)
cd frontend && npm run build            # собрать SPA -> frontend/dist
cd ../backend
NEGO_AI=api NEGO_JUDGE=1 uvicorn app.main:app --port 8010   # judge авто-он для api/openai
# открыть http://localhost:8010  — main.py отдаёт собранный SPA той же процессой
```

- **`NEGO_AI=api`** (ChatAnthropic) или **`NEGO_AI=openai`** (`gpt-5-nano`, дёшево) —
  ответ за секунды. **Не `cli`** на сцене: локальный CLI ~20–25 с, event loop ждёт.
- **Same-origin** (SPA отдаёт бэкенд на :8010) → нет отдельного Vite-прокси и нет
  1500 мс WS-таймаута, который роняет фронт в мок. Мок остаётся только как
  осознанный аргумент «работает без сети».
- **`VITE_MOCK` не выставлять** (=0): в prod-сборке мок-фолбэк отключён.
- **Прогреть WS** до выхода (открыть страницу, начать сессию, увидеть бейдж
  **«⚖ судит ИИ по смыслу»** — он загорается только при живом судье).

**Проверка перед сценой:** бейдж горит · первый ход отвечает за секунды · в разборе
3/3 интереса и размен · грейд A на золотом пути (ниже).

---

## 2. Структура показа (≈3–5 мин; демо = питч)

**30 с — боль.** Плохие переговоры стоят компаниям денег и отношений; учить этому
негде, кроме дорогих очных тренингов. «Диалог» — тренажёр-стол, где исход решает
*метод*, а не удача.

**20 с — тезис + отстройка.** Существующие AI-ролплеи (Second Nature и др.) штрафуют
за «не те ключевые слова». Мы оцениваем **смысл**: детерминированный движок —
арбитр состояния и счёта, ИИ-судья читает аргумент по существу. Прозрачно и честно.

**90 с — золотой путь (вживую, сценарий «Контракт с поставщиком»).** См. §3.

**60 с — момент «judge-cam» (A/B спам-против-смысла).** См. §4 — *гвоздь показа*.

**40 с — разбор.** Грейд, «А что если…» реплей пивотного хода, «Что сказал бы
мастер», объяснение потолка по технике. Честный, воспроизводимый, цитирует ваши ходы.

**20 с — роадмап.** Протокол «ход» модальностно-независим → голос (STT/TTS) как
адаптеры на краях без изменения движка. Одна env — переход в прод.

## 3. Золотой путь — сценарий «Контракт с поставщиком» (грейд A)

Оппонент: **Ирина, глава продаж** (стиль relationship, не любит давление).
Старт 100 ₽/шт · её floor 84 · ваша цель ≤86 · красная линия 92 · BATNA: другой
поставщик по 95 с рисками качества. Три скрытых интереса: **загрузка производства ·
денежный поток/предоплата · долгосрочный контракт**. Идеальный размен —
**годовой контракт с гарантией объёма** (для неё дорого, вам дёшево).

Реплики (вопросы → критерий → размен → закрытие; не давить ценой). Формулировки
выверены: каждый вопрос содержит распознаваемый оборот («что для вас важн…»,
«почему для вас…», «что для вас критично») **и** ключевое слово интереса — иначе
движок засчитает его как обычный вопрос и интерес не вскроется:

1. «**Что для вас важнее** всего в этой сделке — стабильная **загрузка
   производства** без простоев?» — *вскрывает интерес №1.*
2. «А **почему для вас важен** **денежный поток** — предоплата, аванс помогли бы?» — *интерес №2.*
3. «**Что для вас критично**: разовая поставка или **долгосрочный контракт** на год?» — *интерес №3.*
4. «По рынку аналог идёт 86–88; альтернатива у нас есть по 95, но с рисками
   качества. Ориентир справедливой цены — около 86.» — *объективный критерий + BATNA.*
5. «Если мы дадим **годовой контракт с гарантией объёма** и **30% предоплату** —
   сможете подвинуться к **86**?» — *размен: её загрузка+долгосрок+кэшфлоу за цену.*
6. «Договорились: **86 ₽/шт**, годовой контракт, предоплата 30%. Фиксируем?» — *закрытие.*

**Проверено детерминированно** (движок, offline keyword-путь): **грейд A**, overall ≈92,
**3/3 интереса**, объективный критерий, размен обоих secondary-issues, сделка **≈85 ₽/шт**
(в ZOPA: выше пола 84, ≤ цели 86). Точное число слегка плавает от формулировок — грейд A
и попадание в ZOPA держатся стабильно. Работает даже без сети — золотой путь надёжен,
даже если на сцене отвалится бэкенд. С живым судьёй результат не хуже. *Распечатать как шпаргалку.*

> Почему не импровизировать: живой набор текста может уйти в тупик, упереться в
> лимит 12 ходов или сорваться в breakdown — F на сцене ломает историю.

## 4. Момент «judge-cam» — A/B спам против смысла (гвоздь)

Показать, что продукт — **не keyword-матчер**. Два хода подряд на том же столе:

- **Спам-салат:** «Рыночная цена ниже, потому что рынок, в обмен на объём, стандарт
  индустрии, это справедливо.» → keyword-лексиконы triggered, но **судья ставит ~20**,
  чип **«распознал шаблон, не смысл»** (зачёркнут), потолок по технике держит грейд.
- **По существу:** «Что для вас важнее — стабильная загрузка или быстрый кэшфлоу?
  Если дадим годовой объём, сможете подвинуться по цене?» → **судья ~80**, загораются
  чипы распознанных техник (вскрытие интереса, размен).

Реплика для жюри: *«Смотрите — ИИ ловит игру в ключевые слова и вознаграждает
реальный метод. Это и есть весь тезис продукта в одном экране.»*

---

## 5. Подстраховка

- **Записать видео-дубль** золотого пути и judge-cam заранее — если сеть на сцене ляжет.
- **Оффлайн-мок = аргумент, а не авария:** отдельно показать «работает без бэкенда»
  (детерминированный движок полностью играбелен) — это про надёжность, не про сбой.
- **Латентность:** индикатор набора держится; медленный/упавший ход ИИ тихо
  откатывается на шаблон персоны — соединение и бейдж судьи не сбрасываются.
- **Не** демонстрировать `NEGO_AI=cli` (медленно) и **не** оставлять `VITE_MOCK=1`.
