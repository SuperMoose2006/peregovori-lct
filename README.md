# 🤝 Диалог — Negotiation Skills Simulator

Интерактивный тренажёр деловых переговоров, где **исход зависит от стратегии, формулировок и
аргументов** игрока. Живой диалог с ИИ-оппонентом, у которого есть **скрытые интересы**, **красная
линия** и **характер**. Каждая реплика анализируется в реальном времени; после игры — разбор с
коучингом. Методики: **Гарвардский метод · SPIN · BATNA**. Проект для хакатона ЛЦТ.

## Режимы

| | Режим | Что это |
|---|---|---|
| 🥋 | **Практика** | один сценарий из библиотеки, живые метрики и подсказки |
| 📖 | **Кампания «Восхождение»** | сюжетная арка из 4 актов (junior → фаундер); **репутация переносится** между актами и влияет на стартовое доверие следующего оппонента |
| 🎯 | **Своя сделка** | опишите свою **реальную** ситуацию — ИИ сгенерирует под неё оппонента и зону торга |
| 🏆 | **Экзамен** | без подсказок и метрик во время игры; в конце — **сертификат** с оценкой |
| 📚 | **Курс приёмов** | девять блоков (позиции и интересы → SPIN → слушание → критерии → BATNA/ZOPA → якорь → размен → давление → закрытие), 37 уроков, 54 упражнения десяти типов, экзамен в каждом блоке. Правильный ответ **доказан против движка**, а не заявлен: банк прогоняется через настоящие `analyze()`/`apply_move()` на обоих языках, поэтому правка баланса, расходящаяся с курсом, валит сборку. Капстоун блока — настоящая партия |

8 сценариев: контракт с поставщиком · зарплата · конфликт отделов · раунд с инвестором · аренда квартиры · покупка авто с рук · ставка фрилансера · продление SLA.

## Как это работает

**Главный инвариант:** состояние игры и оценку считает **детерминированный движок** (метрики, ZOPA,
вскрытие интересов, счёт A–F). **ИИ отвечает только за смысл и за текст реплик оппонента** — при
ошибке, таймауте или отсутствии сети берётся шаблонный фолбэк, и продукт остаётся полностью
играбельным. Это делает тренажёр **прозрачным, честным и воспроизводимым**.

Оценка: `overall = 0.4·экономика + 0.25·отношения + 0.35·техника`. Принципиальная игра (вскрытие
интересов → объективные критерии → размен) ведёт к грейду **A/B**; давление и грубость → **срыв / F**.

**Второй инвариант, равный по силе первому:** грейд, полученный со слоями (голос, камера, лицо),
обязан быть сравним с грейдом без них. Ни один сигнал слоя не входит в оценку — иначе сертификат
экзамена перестаёт что-то значить.

```

                             джиттер-буфер звука, захват микрофона и камеры.
                             src/mock/ — офлайн-ядро: та же игра целиком в браузере.
        │  WS /v1/realtime?mode=text|voice
        ▼
services/gateway/            FastAPI :8010
  realtime/                  сессия · шина событий · владение поколением · отмена
  perception/                ten-vad · детектор конца реплики · сэмплер зрения
```

## Слои модальностей

| Слой | Что делает |
|---|---|
| 🙂 Лицо оппонента | состояния персонажа, переключает **реакция движка** (липсинка нет и он не заявляется) |
| 🎭 Читай лицо | игра спрашивает, что чувствует оппонент; ответ знает движок |
| 🎤 Голосом | говорите вслух и слышите ответ, **можно перебивать** |
| 📷 Камера | сигналы присутствия: кто в кадре, куда смотрите |

Слой, который окружение не может дать (нет https → нет микрофона), честно говорит «недоступно».
Переключателя, который включается и ничего не делает, в продукте не бывает.

## Модели (через OpenRouter)

Роли разведены: судья стоит в критическом пути хода, а реплику оппонента человек слышит вслух.

| Роль | Переменная | Дефолт |
|---|---|---|
| Реплики оппонента | `NEGO_MODEL_OPPONENT` | `google/gemini-3.5-flash-lite` |
| Судья каждого хода | `NEGO_MODEL_JUDGE` | `google/gemini-3.5-flash-lite` |
| Зрение | `NEGO_MODEL_VISION` | `google/gemini-3.1-flash-lite` |
| Разбор, генерация сценария | `NEGO_MODEL_REASONING` | `z-ai/glm-5.3` |
| Распознавание речи | `NEGO_MODEL_ASR` | `google/gemini-3.7-flash` |

`NEGO_MODEL_OPPONENT=moonshotai/kimi-k3` — максимальное качество для демо.
`NEGO_AI=off` — полный офлайн. Синтез речи по умолчанию **edge-tts**: русский голос важнее
идеологической чистоты «всё через один шлюз».

## Быстрый старт

```bash
make install          # venv гейтвея + npm
make gateway          # FastAPI на :8010
make frontend         # Vite на :5173 (проксирует /v1/realtime и /api)
make test             # 286 бэкенд + 130 фронтенд

# ключ — в gitignored services/gateway/.env:
#   OPENAI_API_KEY=sk-or-...
#   OPENAI_BASE_URL=https://openrouter.ai/api/v1
```

Собранный фронт раздаётся самим гейтвеем (`cd frontend && npm run build`, затем
`http://localhost:8010/`) — один процесс на весь продукт. Без гейтвея страница уходит в офлайн-ядро
и остаётся полностью играбельной.

Аватар с липсинком — отдельный сервис на машине с GPU, см.
[`services/avatar/README.md`](services/avatar/README.md). Без него работает провайдер состояний.

## Тесты и верификация

- **286 тестов гейтвея**: движок, realtime-протокол, отмена поколения, паритет голоса и
  клавиатуры, переподключение, падение ИИ, слои против оценки, а также **банк курса**
  — каждый пункт прогоняется через настоящие `analyze()`/`apply_move()` на обоих языках.
- **130 тестов фронтенда**: паритет офлайн-ядра с движком (включая пословную сверку
  классификатора по фикстуре из Python), токены, конвенция пометок, паритет словарей
  RU/EN, прогресс курса.
- Голосовой круг проверен вживую: синтез по-русски → распознавание возвращает ту же фразу.
- Перебивание проверено вживую: отмена за 244 мс, ноль чанков после неё.
- Все режимы проверены в браузере (Playwright) — скриншоты в `docs/screenshots/`.
- `make preflight` — проверка перед показом: собран ли фронтенд, жив ли гейтвей,
  включён ли ИИ и судья, на месте ли лица, маскоты и шрифт, синхронно ли зеркало
  курса. Отличает «показывать нельзя» от «пойдёт, но знайте про это».
- `make e2e` — две браузерные проверки:
  **обход экранов** (падает, если где-то ошибка в консоли, экран не открылся или
  провал экзамена не привёл к уроку восстановления) и **сквозной проход блока
  курса эталонными ответами** — все уроки, все задания и экзамен через настоящий
  интерфейс; падает, если эталонный ответ не зачтён или блок не открыл следующий.
  Юнит-тесты этого не ловят: половина поломок здесь была не в логике, а в том, что
  кнопка ушла за сгиб или подложка стала прозрачной.
