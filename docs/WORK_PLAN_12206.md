### avatar-lipsync — высокий риск

Затрагиваются app/avatar/base.py, presence.py, новый адаптер реального
провайдера, orchestrator/negotiation.py и tts_manager.py, realtime/endpoint.py,
frontend/src/components/OpponentFace.tsx, realtime/transport.ts и типы capabilities.
Переиспользовать AvatarProvider и существующий аудиопуть; не запускать отдельный
speech-to-speech движок. Сначала выяснить из передачи доступный провайдер,
GPU/транспорт/вход аудио, отмену и лицензии. Потом контракт и адаптер за явным
включением; затем клиентский рендер и безопасный возврат к портрету.

Проверки: capabilities правдивы при недоступном провайдере; передаётся именно
озвучиваемый текст/звук; нет второго проигрывания аудио; перебивание гасит
старое поколение; разрыв видео не ломает текстовую партию. Поддельный провайдер
доказывает только контракт. Настоящую синхронизацию проверять реальной записью
звука и кадров, без синтетического ввода. Пока нет такого прогона, не заявлять
lipsync как проверенный. Риск: двойной звук, очередь старого видео, задержка,
неработающий GPU. На стенд для этой части ходить запрещено исходным мандатом.

### probe — средний риск

Файлы: app/protocol.py, realtime/events.py, realtime/session.py,
orchestrator/negotiation.py, новый чистый модуль расчёта вне engine;
frontend/src/types.ts, realtime/transport.ts, lib/probe.ts, mock/mockServer.ts;
документация закрытого списка событий; Python/TS тесты и общие фикстуры.

Реализованный порядок: turn.analysis → judge → apply_move → обработка
лимита ходов → engine.state → ответ оппонента → response.done → probe.
Расчёт использует окончательную реакцию; доставка после ответа сохраняет
прежний момент показа. При отменённой доставке память вопроса не продвигается.
Нельзя использовать предварительный разбор: судья меняет исход, а лимит может
закрыть стол после apply_move. Поля сохранить: turn, options, answer; имя probe
завести в SERVER_EVENTS. Вопрос не принадлежит аудиопоколению: перебивание
не отменяет уже совершённый ход. Память lastTurn/lastReaction принадлежит
RealtimeSession и сохраняется существующим механизмом resume; сбрасывается
только для новой партии. Слои выключены на exam/drill сервером.

Перенести nextProbe/buildProbe с точным 32-битным FNV/LCG и порядком дистракторов;
оставить JS-расчёт в офлайн-ядре и офлайн-режиме чтения стола. Онлайн-транспорт
принимает серверный вопрос, сам его не рассчитывает. При необходимости хранит
до response.done, чтобы сохранить нынешний момент показа после реплики; это
буфер отображения, не второй расчёт. Проверить reducer перед выбором момента.
Не вводить скрытый fallback на клиентский расчёт для старого сервера.

Проверки: все реакции включая probe_vague, неизвестная реакция, ходы 1–12,
такт 3 и единственная отсрочка повтора, закрытие/таймаут, layer off, exam/drill,
две независимые сессии, resume, отмена речи, отсутствие дубликатов. Общие
Python/TS фикстуры для options и answer. Настоящий WS + подставной судья,
меняющий реакцию, доказывают источник ответа. Тест транспорта проверяет, что
engine.state без probe не создаёт вопрос; серверный probe передаётся ровно один
раз. Мутации: расчёт до apply_move, неверный answer, сброс памяти при resume,
возврат клиентского nextProbe, отправка на закрытом столе.

## Эксплуатация ASR

Только по рецепту передачи: проверить существующий процесс/порт/пользователя,
EnvironmentFile (значения не печатать), executable и рабочий каталог;
установить один юнит, daemon-reload, enable; выполнить контролируемый переход
от старого процесса без второго listener и restart службы. Проверить active,
enabled, MainPID, endpoint и настоящий запрос распознавания, источник ASR и
отсутствие fallback. Restart службы не равен перезагрузке хоста: отдельно
указать, проверялся ли реальный reboot. Не перезагружать весь стенд ради
доказательства без необходимости из передачи, не трогать остальные службы.
