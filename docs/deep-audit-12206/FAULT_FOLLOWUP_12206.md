## D8: потеря заработанного прогресса второй вкладкой

Реальный путь с **нулевым профилем**, без разблокирующих снимков:

1. Открыть урок1 во вкладкеA и урок3 во вкладкеB до первого сохранения.
2. Полностью пройти урок1, затем полностью пройти урок3.
3. Перезагрузить обе вкладки, открыть блок и сверить отметки, solved и XP.

До исправления обе локали теряли урок1: оставался только урок3. Причина —
CourseScreen сохранял целиком профиль, захваченный вкладкой при открытии.
Исправление читает текущий профиль перед пятью записями CourseScreen/Warmup;
при недоступном/пустом хранилище используется текущий профиль, а не новый пустой.
При failed save сохраняется память вкладки: прежний blob на диске не отменяет
уже заработанное в этой вкладке. После успешной записи этот резерв очищается.

`course-tabs-faults.mjs`: before RU/EN красные; after RU/EN зелёные. Мутация
`loadProfile(profile)`→`profile` подставлена только в ответ Vite внутри своего
браузера, без редактирования рабочих исходников: оба `mutation-verified` красные
именно по потере урока1. Прибор отдельно требует фактической подмены модуля.
Первый вариант маски мутации не учитывал query string Vite и остался зелёным;
он **исключён из доказательства**. Его результаты сохранены для честности.

```sh
cd frontend
CHROME_PATH=/path/to/headless-shell AUDIT_LANG=ru AUDIT_TAG=after node --import tsx e2e/course-tabs-faults.mjs
CHROME_PATH=/path/to/headless-shell AUDIT_LANG=en AUDIT_MUTATION=stale-profile AUDIT_TAG=mutation-verified node --import tsx e2e/course-tabs-faults.mjs
```

Результаты: `tmp/course-tabs-{ru,en}-{before,after,mutation-verified}/results.json`.
Первый запуск с системным Chrome завис до первого сценария; остановлен только
свой процесс, затем использован отдельный headless-shell. К окнам владельца
обращений не было. Собственные Vite15416/15418 остановлены после проверок.

Дополнительно `profile-storage.test.ts` проверяет сохранение обоих уроков,
