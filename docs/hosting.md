# Показ по сети: почему сертификат обязан быть настоящим

Тренажёр просит микрофон и камеру. Это «мощные возможности» браузера, и они
живут не в HTTPS вообще, а в **доверенном** HTTPS. Разница не косметическая, и
она измерена.

## Что ломает самоподписанный сертификат

Первый показ стоял на `https://185.154.194.88:8443` с самодельным сертификатом.
Замер (`frontend/probes/`) на этом хосте:

```
защищённый контекст: true
service worker: НЕТ
ошибок: 1 — «An SSL certificate error occurred when fetching the script»
```

Контроль на `http://127.0.0.1:8010` (доверенный origin без сертификата вовсе):
service worker **зарегистрирован**. Значит дело не в коде и не в самом файле —
браузер отказывает именно этому происхождению.

Service worker — только видимая часть. `window.isSecureContext` возвращает
`true` и после того, как человек прощёлкал предупреждение, поэтому по этому
флагу ничего не видно; но происхождение с ошибкой сертификата остаётся
«ненадёжным», и на телефонах (в первую очередь Safari на iOS) запрос
`getUserMedia` на нём отклоняется без вопроса пользователю. Голосовой и
камерный слои на демонстрации просто не включаются, а офлайн-оболочка не
ставится.

Вывод короткий: **самоподписанный сертификат — это не «HTTPS с предупреждением»,
это половина продукта.**

## Что стоит сейчас

```
https://185-154-194-88.nip.io        (порт 443, без порта в адресе)
логин dialog · пароль в NEGO_HTTP_PASSWORD
```

Домена у стенда нет, есть только адрес. `nip.io` разрешает
`185-154-194-88.nip.io` в `185.154.194.88`, а Let's Encrypt выдаёт на такое имя
обычный сертификат. Проверка HTTP-01 занята: порт 80 держит посторонний
контейнер, трогать его нельзя. Поэтому проверка идёт по TLS-ALPN-01 на 443 —
её умеет `acme.sh`, но не `certbot`.

Замер на этом хосте, тем же прибором:

```
защищённый контекст: true
service worker: зарегистрирован
getUserMedia: ok:video · ok:audio
кадров ушло: 19 · зрение ответило: «В кадре отсутствует человек…»
ошибок: 0
```

## Выпуск и продление

Состояние acme.sh лежит в `/root/.acme.sh` (не в репозитории — там ключ).

```bash
# выпуск
/root/.acme.sh/acme.sh --home /root/.acme.sh \
  --issue --alpn --tlsport 443 -d 185-154-194-88.nip.io --server letsencrypt

# продление: 443 обязан быть свободен на время проверки, значит гейтвей
# останавливается, продлевается сертификат, гейтвей поднимается снова
/root/.acme.sh/acme.sh --home /root/.acme.sh --renew --alpn --tlsport 443 \
  -d 185-154-194-88.nip.io --ecc
```

Срок текущего — до 24 ноября 2026, окно продления открывается 24 октября.

**Продление РУЧНОЕ.** Обычно acme.sh ставит себе задание в cron сам; здесь
`crontab -l` пуст, а значит никто не продлит сертификат за вас, и в один день
демо просто перестанет открываться. Проверить срок:

```bash
openssl x509 -in services/gateway/certs/le-fullchain.pem -noout -dates
```

Файлы копируются в `services/gateway/certs/` (каталог в `.gitignore`):

```bash
S=/root/.acme.sh/185-154-194-88.nip.io_ecc
cp $S/fullchain.cer services/gateway/certs/le-fullchain.pem
cp $S/185-154-194-88.nip.io.key services/gateway/certs/le-key.pem
chmod 600 services/gateway/certs/le-key.pem
```

## Запуск

```bash
cd services/gateway && set -a && . ./.env && set +a && \
  PYTHONPATH=/root/LCT ./.venv/bin/uvicorn app.main:app \
    --host 0.0.0.0 --port 443 \
    --ssl-keyfile certs/le-key.pem --ssl-certfile certs/le-fullchain.pem
```

**Перезапуск после правок кода.** Шлюз — долгоживущий процесс: он держит в
памяти тот код, с которым поднялся. Однажды процесс, раздававший демо, крутился
двое с половиной суток и отвечал позавчерашним кодом — курс на диске знал
упражнение, живой процесс нет. `/api/health` отдаёт отпечаток `build`, и
`make preflight` сверяет его с диском; но проверять надо ПОМНИТЬ, поэтому
правило простое: правили бэкенд — перезапустите процесс.

В отпечатке четыре поля, и последнее появилось не сразу. Три счётчика —
`exercises`, `scenarios`, `campaigns` — считают СОДЕРЖИМОЕ, и за день правок
судьи, голоса, лицензионных шапок и пределов ни один из них не шелохнулся:
90, 9, 2. Прибор, поставленный ловить старый код, кода не видел. Поэтому рядом
стоит `code` — хеш всех `.py` пакета `app`, снятый в момент СТАРТА процесса
(`services/gateway/app/main.py::_code_digest`). Именно старта, а не текущего
диска: диск с тех пор мог уехать вперёд, а вопрос всегда один — с чего поднялся
этот процесс.

```bash
kill $(ss -ltnp | grep ':443 ' | grep -o 'pid=[0-9]*' | cut -d= -f2)
# затем команда запуска выше
```

Фронтенд перезапуска не требует: статику шлюз читает с диска, достаточно
`npm run build`.

## Пароль обходится любым локальным прокси — и однажды обошёлся

Замок стоит на входе с улицы, а не между комнатами: обращения с `127.0.0.1` не
проверяются, потому что через них ходят OpenTalking, приборы и скриншотные
прогоны. Следствие неочевидное и дорогое: **любой процесс на этой машине,
который слушает наружу и проксирует на шлюз, отдаёт продукт в интернет мимо
пароля** — запрос приходит с лупбэка, то есть уже «своим».

Это не гипотеза. 29 августа на машине два часа работал `vite --host 0.0.0.0` на
порту 5174. Дев-сервер проксирует `/api` и `/v1/realtime` на `:8010`. Снаружи
`http://185.154.194.88:5174/api/health` отвечал 200 с полной раскладкой моделей,
и тем же путём открывался сокет — то есть чужой мог играть на наших ключах.

Две заплатки. `frontend/vite.config.ts` привязан к `127.0.0.1`, чтобы наружу
нельзя было выйти НЕЧАЯННО (явный `--host` это перебьёт — запрет не абсолютный).
И сторож на живой машине:

```bash
cd services/gateway && .venv/bin/python tools/listeners_check.py
```

Он перечисляет слушателей, отделяет наши от чужих и ругается на два случая:
наша раздача наружу мимо портов 443 и 8443, и чужой сервер на порту, который
занят рецептом пробы. Второе — тоже не гипотеза: `probes/README.md` отводит
5199 под офлайн-сборку, а порт держал вчерашний `vite preview` со
`--strictPort`, из-за чего команда запуска тихо не срабатывала, а обходчик
рапортовал «ноль замечаний» по чужой сборке.

Правило: перед показом — `listeners_check.py`, и он обязан молчать.

Пароль берётся из `NEGO_HTTP_PASSWORD` в `.env`. Пусто — вход открыт;
задан — внешние запросы просят пароль, локальные (OpenTalking, приборы,
скриншоты) не трогаются. Веб-сокет пароля в заголовке не получает — браузер его
там не шлёт, — поэтому успешная проверка HTTP оставляет куку `dlg_ok`, и
`/v1/realtime` проверяет её.

## Пароль — не единственная защита: пределы на адрес

Пароль на показе знают все, кому его назвали, поэтому за ним стоят пределы на
один адрес (`services/gateway/app/realtime/limits.py`). Числа не круглые, они
посчитаны и объяснены прямо в этом файле:

| Что | Значение | Переменная |
|---|---|---|
| партий одновременно с адреса | 12 | `NEGO_MAX_SESSIONS_PER_HOST` |
| вызовов модели зрения в секунду | 2, ведро 20 | `NEGO_VISION_CALLS_PER_S`, `NEGO_VISION_BURST` |
| ходов в секунду | 4, ведро 16 | `NEGO_TURNS_PER_S`, `NEGO_TURN_BURST` |

Два свойства, которые важно знать хозяину стенда:

- **Предел ходов ЗАДЕРЖИВАЕТ, а не отказывает.** Клиент, отправив ход, ждёт
  `response.done`; отказ лёг бы строкой в ленту и оставил человека перед вечным
  «оппонент печатает».
- **Локальные адреса не ограничиваются** — через них ходят OpenTalking, приборы
  и предпоказ; и **в офлайне (`NEGO_AI=off`) предел молчит**: провайдера нет,
  придерживать нечего.

Тринадцатая партия с адреса места не получает: отказ идёт словами и отдельным
кодом закрытия, чтобы клиент не принял его за обрыв сети и не пошёл
переподключаться. Возврат в СВОЮ брошенную партию отказом не считается — там
вытеснение: новый сокет забирает стол, прежний слышит причину на своём языке.

До них ёмкость упиралась не в нас. Здесь долго стояло число «сто двадцать
сокетов», полученное неизвестно чем: прибора, которым его снимают, в
репозитории не было. Теперь есть — `services/gateway/tools/bench_load.py`, — и
число оказалось меньше правды в семнадцать раз.

## Сколько шлюз держит на самом деле

Прогон бесплатный: `NEGO_AI=off` даёт полностью играбельную партию без единого
обращения к модели, и пропускную способность своего кода мерят именно так.
Каждая сессия в прогоне ИГРАЕТ — шлёт ход и ждёт, пока движок ответит
`engine.state` с нужным номером; в счёт идут доигранные ходы, а не открытые
сокеты.

```bash
cd services/gateway && NEGO_AI=off .venv/bin/uvicorn app.main:app --port 8010 &
.venv/bin/python tools/bench_load.py --ramp 1,12,32,128,512,1024,2048 --turns 3
```

Замер на этой машине (два ядра, 4 ГБ, шлюз и прибор на одной коробке):

```
 партий  создано        ходов   медиана     p95    макс   RSS МБ     fd   ядра
      1        1          3/3         1       1       1     77.4     16      —
     12       12        36/36         7       8       8     78.5     27      —
     32       32        96/96        19      21      22     81.3     47      —
    128      128      384/384       122     156     168     93.3    143      —
    512      512    1536/1536       315     379     393    134.0    527   0.92
   1024     1024    3072/3072       584     735     744    184.5   1039   0.95
   2048     2048    6144/6144      1423    1640    1732    289.1   2063   0.91
```

**2048 одновременных партий, 6144 доигранных хода, ни одного отказа и ни одной
потери.** Столбец «медиана» — миллисекунды от отправки хода до ответа движка.

**Что упирается первым — не то, что кажется.** Ни память, ни дескрипторы:
партия стоит 0.10 МБ и один дескриптор при потолке в миллион. Первым
насыщается ЕДИНСТВЕННЫЙ цикл событий — 0.9 ядра уже с пятисот партий, — и
дальше растёт не число отказов, а очередь к нему: 0.69 мс задержки хода на
каждую одновременную партию. Продукт не падает, он замедляется. Лестницу на
ступени 3072 оборвал сторож памяти самого прибора, и это память МАШИНЫ, а не
шлюза: прибор и шлюз делят одну коробку на четыре гигабайта.

**Очереди у шлюза нет.** `session.queued` и `session.queue_update` есть в
протоколе (клиент — порт upstream-овского `realtime-session.js` — ждёт события
перед `session.init`), но не отправляются ни разу: `session.queue_done` уходит
сразу. Приёмный контроль — это потолок партий на адрес и очередь ядра на
`accept` (uvicorn берёт её по умолчанию, 2048), а не наша очередь. Проверено
тестом, а не обещано.

**Значит, что именно закрывают пределы.** Не «пятнадцать платных вызовов в
секунду», а 256: две тысячи партий, каждая со взглядом раз в восемь секунд. Ход
дороже взгляда втрое — судья, поток реплики оппонента, синтез, — и тем же
прибором с одного адреса без придержки проходило 1399 ходов в секунду. Предел
на адрес — решение про кошелёк, а не про ёмкость.

## Пределы проверены на проводе, а не в вызове функции

```bash
.venv/bin/python tools/bench_load.py --mode limits   # потолок партий
.venv/bin/python tools/bench_load.py --mode pace     # темп ходов
```

Пределы проверяются с адреса `127.0.0.2`: для ядра это та же петля, а для шлюза
уже «улица» — `LOCAL_HOSTS` это ровно `127.0.0.1`, `::1`, `localhost`. Так
предел виден на проводе, и наружу при этом ничего не открывается.

Следствие, о которое прибор уже споткнулся: раз это «улица», то и **пароль
стенда с неё спрашивают**. Без него сокет закрывается ДО рукопожатия (403), и
первая редакция приговора гласила «предел не держится» — обвинив исправный
предел в чужой беде. Теперь потери называются отдельно, а пароль прибор берёт
из `NEGO_HTTP_PASSWORD` (или из `--password`) и предъявляет той же кукой
`dlg_ok`, что и браузер:

```bash
cd services/gateway && set -a && . ./.env && set +a && \
  .venv/bin/python tools/bench_load.py --mode limits
```

| Что спросили | Что ответил шлюз |
|---|---|
| 16 партий одновременно при потолке 12 | создано 12, отказано 4, код `too_many_sessions`, закрытие 4429 |
| свежее соединение поверх выбранного потолка | места не получает |
| закрыли партию — просим ещё | место вернулось |
| 60 ходов подряд с одного адреса | установившиеся ровно 4.0 хода в секунду |
| свежий сокет с ТОГО ЖЕ адреса после залпа | первый ход ждал 248 мс |
| свежий сокет с соседнего адреса | первый ход 1 мс |

Последние две строки и есть ответ на «а нельзя ли обойти переоткрытием»: ведро
живёт в модуле и ключуется адресом, сокет о нём не знает ничего. 248 мс — это
ровно такт ведра при четырёх ходах в секунду.

Оговорка, которую нельзя проглатывать: **в офлайне придержка ходов выключена по
построению** (`turn_delay` возвращает ноль при `NEGO_AI=off` — платных вызовов
нет, придерживать нечего). Чтобы померить её бесплатно, шлюз поднимают БЕЗ
`NEGO_AI=off`, но и без ключей: придержка работает, а реплику даёт шаблонный
фолбэк. Именно так сняты 4.0 хода в секунду.

## Комната жюри: держит ли продукт десяток-другой партий за одним NAT

Это главный практический вопрос показа, и ответ на него **нет, не держит** —
если комната больше двенадцати человек.

```bash
.venv/bin/python tools/bench_load.py --mode room --room 20 --turns 4 --think 8
```

| Настройки стенда | Комната 20 | Комната 30 |
|---|---|---|
| как сейчас (12 / 4 в с, ведро 16) | 12 партий из 20, восьми отказано | — |
| `NEGO_MAX_SESSIONS_PER_HOST=40` | все 20 играют, ход до 1005 мс | все 30 играют, ход до 3489 мс |
| то же плюс `NEGO_TURNS_PER_S=8`, `NEGO_TURN_BURST=48` | — | все 30 играют, ход до 21 мс |

Читается это так. Тринадцатый человек за одним NAT получает
`too_many_sessions` — не «медленно», а отказ. Поднять один только потолок
партий мало: два других числа ВЫВЕДЕНЫ из него (взгляды: 12 партий / 8 с ≈ 1.5
вызова в секунду → 2; ходы: 12 / 2.45 с ≈ 4.9 → 4), и комната из тридцати
человек, севшая за столы одновременно, начинает ждать хода по три с половиной
секунды — это уже придержка, а не отказ, но на показе она выглядит как
задумавшийся сервер.

**Что делать на площадке.** Если жюри смотрит с одного адреса и столов больше
десяти — поднять три переменные ВМЕСТЕ, по той же арифметике, что записана в
`limits.py`:

```bash
# комната до сорока партий с одного адреса
NEGO_MAX_SESSIONS_PER_HOST=40   # столов за одним NAT, с запасом на resume
NEGO_VISION_CALLS_PER_S=6       # 40 партий / 8 с = 5, плюс калибровка
NEGO_VISION_BURST=48            # первый взгляд каждой партии идёт сразу
NEGO_TURNS_PER_S=8              # вдвое выше человеческого темпа комнаты
NEGO_TURN_BURST=48              # комната садится за столы одновременно
```

Ёмкости шлюза это не касается вовсе: сорок партий он не заметит — замер выше
говорит про две тысячи. Поднимая пределы, поднимают допустимый счёт от
провайдера, и только его. Если стенд стоит на живых моделях, считать надо
кошелёк: сорок партий × три платных вызова на ход.

## Что стенд отдавал наружу и почему это стоит перечитать

29 августа обстрел протокола нашёл в SPA-фолбэке обход каталога: `GET
/../../services/gateway/.env` возвращал 200 и содержимое — ключ OpenRouter. Тем
же запросом отдавался `/etc/passwd`. Дыра была открыта ровно столько, сколько
стенд смотрел в интернет.

**Ключ считается скомпрометированным.** Пароль на HTTP тут не защита: его знают
все, кому его назвали на показе, а ключ — не их. Ключ надо перевыпустить в
личном кабинете OpenRouter и заменить в `services/gateway/.env`; старый —
отозвать. Того же требует ключ OpenAI из `OPENAI_REALTIME_KEY`, если он лежал в
том же файле.

Проверка, что дыры нет (должно вернуться содержимое `index.html`, а не файла):

```bash
curl -s -u dialog:ПАРОЛЬ --path-as-is \
  'https://185-154-194-88.nip.io/../../services/gateway/.env' | head -c 40
```

Урок общий: **каталог со статикой — это граница доверия.** Путь приходит с
улицы, и проверять его надо после `realpath`, а не отсечением «..» в строке:
символьная ссылка внутри `dist` ведёт наружу без единой точки в пути.

## Обход через комнату: полная перепись дверей

Два случая выше — обход каталога в раздаче статики и дев-сервер, проксирующий
на шлюз, — оказались одним классом: **замок стоит на входе с улицы, а обойти
его можно через комнату.** Поэтому двери пересчитаны все, а не только те, где
уже болело. Что нашлось.

### Шов OpenTalking был открытым прокси к нашему платному ключу

Адаптер `adapters/opentalking_negotiation.py` добавляет в то же приложение три
ручки: `POST /v1/chat/completions`, `POST /v1/audio/speech`, `GET /v1/models`.
Первые две **не отвечают сами** — они пересылают тело запроса в OpenRouter
нашим ключом и возвращают ответ провайдера как есть. Модель и содержимое берутся
из запроса, то есть с улицы.

Значит это был не «наш движок под видом LLM», а прокси к платному API: любая
модель, любой промпт, ответ обратно. Ни `NEGO_AI=off`, ни пределы на адрес
(`app/realtime/limits.py`) их не касались вовсе — те стоят на партии, а здесь
партии нет. Единственной защитой оставался пароль; про пароль см. раздел выше.
Проверено живым запросом к стенду: ответ пришёл от чужой модели, названной в
теле запроса.

**Починено:** роутер монтируется с проверкой «только с этой машины»
(`app/main.py::_local_only`), улице обе ручки отвечают 404. OpenTalking живёт
на :8210 здесь же и ходит с 127.0.0.1 — голосовой путь не тронут. Сторожит
`tests/test_external_surface.py`.

### Четвёртая дверь в платные модели не была посчитана

Пределы на адрес закрывали партии, взгляды камеры и темп ходов. Три платных
вызова стояли мимо них, потому что ни один из них не «ход»:

| Что | Где | Чем стало |
|---|---|---|
| кнопка 💡 | `coach.request` → `_send_hint` | ведро хода; при пустом ведре человек получает подсказку движка |
| тренер курса | `POST /api/course/coach` | ведро хода; при пустом — `note: null`, карточки просто нет |
| «своя сделка» | `session.init {gameMode: custom}` | ведро хода; отказ словами, готовые столы никуда не делись |

Ведро — то же самое, что у хода (`limits.paid_slot`): кошелёк один, адрес один.
Разница с ходом в том, что здесь **отказ, а не придержка**: ход придерживают,
потому что клиент ждёт `response.done` и отказ оставил бы человека перед вечным
«оппонент печатает». У этих трёх есть честный бесплатный ответ, поэтому держать
соединение занятым незачем.

Отдельно проверено, что **переоткрыть соединение — не способ обнулить бюджет**:
вёдра живут в модуле и ключуются адресом, сокет о них не знает ничего.

### Эхо чужой строки

Два места возвращали присланное обратно без обрезки: `unknown scenario:`
в сокете (пять мегабайт в поле → пять мегабайт в ответе) и стандартный ответ
FastAPI на 422, который кладёт в тело поле `input` — то есть **вдвое больше,
чем прислали**, и это работает на голом REST, без партии и без ключа. Оба
обрезаны; форма ответа теперь одна на весь продукт: `поле: причина`, без
значения.

Туда же: `situation` для «своей сделки» уезжала в самую дорогую роль целиком и
не была ограничена ничем — теперь 1500 знаков, отказ называет поле.

### Раздача статики: проверена ещё раз, другими написаниями

Обход не вернулся. Проверено прогоном по живому шлюзу: `..%2f`, `%2e%2e`,
`....//`, `..;/`, двойное кодирование, `%c0%af`, `/etc/passwd` напрямую — всё
отдаёт `index.html`. **Символьная ссылка изнутри `dist` наружу тоже не
проходит** (проверено настоящей ссылкой на `.env`), и это главное: защита стоит
на результате `realpath`, а не на поиске «..» в строке.

Одно нашлось: **нулевой байт в пути** ронял `realpath` необработанным
`ValueError` — 500 и стек в логе вместо страницы. Утечки не было, но 500 на
внешней поверхности означает «здесь что-то не предусмотрено» и приглашает
искать дальше. Починено: путь, который не удалось даже разобрать, — просто не
файл.

### Идентификатор партии — это ключ на предъявителя

`resume` не спрашивает ни адреса, ни пароля: предъявивший id забирает стол, а
прежнего владельца вытесняет. Так и надо — в метро адрес меняется, и привязка
к нему сломала бы главный сценарий возвращения. Но раз это ключ на
предъявителя, его длина перестаёт быть косметикой: было пять байт, то есть
сорок бит на всю защиту чужой партии. Стало шестнадцать; стоит столько же.

Промах по чужому id не отличается от обычного начала партии — `resume`
не работает оракулом «а есть ли такая партия».

### Реплика модели на экране

Санитайзер (`app/ai/sanitize.py`) markdown и выход из роли чистит, а разметку
(`<script>`) **не режет — и не должен**. Экран защищён тем, что реплика едет в
React текстовым узлом и экранируется; вторая, неполная защита рядом с полной
только создаёт впечатление, что можно расслабиться, и попутно ломает законное
«прибыль > 10%». Единственное место вставки сырого HTML в клиенте кормится
строками словаря i18n — это проверяется тестом, и он сломается, если реплика
туда однажды поедет.

А вот своей работы санитайзер не делал: проверка выхода из роли ищет
**подстроку**, и её рвал любой невидимый знак. Один символ нулевой ширины
внутри слова — и «как языковая модель» проезжало мимо всех маркеров на экран
и, что хуже, в озвучку. Туда же — `U+202E`: он переставляет цифры в глазах
читателя, то есть цена в пузыре переставала совпадать с ценой в `engine.state`.
Починено: невидимое и управляющее убирается ДО того, как реплику начинают
судить по содержимому.

## Что остаётся открытым — и почему

### Реплику игрока читает судья, и это дверь в его промпт

Текст хода подставляется в промпт судьи как есть. Значит игрок может обратиться
к судье через собственный ход. Фильтром это не чинится: любой признак «похоже
на инструкцию» обходится перефразированием, а ложное срабатывание отняло бы
балл у честной реплики.

Чинится это тем, что **послушный судья не владеет ничем важным**, и вот граница
ровно:

- Балл судьи зажат в 0..100, индекс интереса проверен по списку сценария, id
  вторичного вопроса — по его же списку, ярлыки приёмов — по закрытому
  словарю (`app/ai/judge.py::_validate`).
- **Вето только отнимает.** Приём начисляется, только если его нашёл
  детерминированный разбор; судья может его снять, но не может выдумать. То
  есть рычага и движения цены на пустом месте не бывает.
- Дно оппонента считает движок. Проверено прогоном: судья, отвечающий игроку
  «да» на всё, двенадцать ходов подряд, на всех девяти сценариях — оппонент
  не переходит `opponent_reservation`.
- **В партии на зачёт семантического судьи нет вовсе**
  (`protocol.REPRODUCIBLE_MODES`). Сертификат считает движок, а движок читает
  только текст ходов, где инъекция — просто слабый ход: ни критерия, ни
  размена, ни BATNA в ней нет.

Что при этом остаётся открытым честно: **в практике захваченный судья может
поднять игроку балл хода и вскрыть один интерес раньше срока.** Партия на
зачёт этим не затронута, оценка на сертификате — тем более. Дороже этого
чинить нечем.

### Пароль знают все, кому его назвали

Не изменилось и измениться не может: пароль один на показ. Он защищает от
прохожего, а не от гостя. Всё, что за ним, обязано иметь второй предел — этим
и занимаются вёдра на адрес.

### Локальный прокси по-прежнему обходит пароль

Механика та же, что описана выше: обращения с 127.0.0.1 не проверяются, и любой
процесс, который слушает наружу и проксирует на шлюз, отдаёт продукт мимо
пароля. `tools/listeners_check.py` ловит **наши** листенеры, ушедшие наружу; про
чужой процесс, решивший проксировать на :8010, он знать не может. Правило
остаётся ручным: перед показом — `listeners_check.py`, и он обязан молчать.

### Порт 8443 увели с улицы на петлю

Сторож разрешал нашей раздаче наружу порты 443 и 8443, и на 8443 висел второй
процесс со **старым самоподписанным сертификатом** и с кодом настолько давним,
что в его здоровье ещё не было поля `code` (90 упражнений против нынешних 101).
Сторож про него молчал: порт был разрешён. То есть у отпечатка сборки появилось
слепое пятно ровно там, где он нужнее всего, — на процессе, который никто не
перезапускал.

Погасить его было нельзя: **медийные пробы требуют TLS**, без него браузер не
даёт ни микрофона, ни камеры, и `probes/_fresh.mjs` ходит именно туда. Поэтому
он не погашен, а переставлен на `127.0.0.1`: снаружи его больше нет, пробам он
остался. Из списка разрешённых наружу портов 8443 убран — теперь там ровно один
адрес, и всякий второй сторож назовёт.

```bash
cd services/gateway && set -a && . ./.env && set +a && \
  PYTHONPATH=/root/LCT ./.venv/bin/uvicorn app.main:app \
    --host 127.0.0.1 --port 8443 \
    --ssl-keyfile certs/key.pem --ssl-certfile certs/cert.pem
```

Правило прежнее и теперь исполнимо: **наружу смотрит ОДИН стенд.**

### Размер запроса ничем не ограничен

У uvicorn нет предела на тело запроса, и мы его не задаём. Отражение обратно
закрыто (см. выше), но принять и разобрать многомегабайтное тело шлюз всё ещё
согласится. Для показа за паролем это приемлемо; для открытого стенда предел
задаёт обратный прокси, которого у нас нет.

### `/openapi.json`, `/docs`, `/redoc` открыты за паролем

FastAPI поднимает их сам. Они не дают ничего сверх схемы (имена полей ручек),
но перечисляют и те маршруты, которые улице отвечают 404. За паролем это
приемлемо; отключать их — отдельное решение, а не следствие этой проверки.

### Чего эта проверка НЕ доказывает

- Приборы прогонялись по **шлюзу**, а не по боевому процессу на :443. Тот
  поднялся раньше правок и отвечает своим кодом — **после этих правок стенд
  надо перезапустить**, иначе всё вышеописанное чинит только диск.
- Замена букв похожими (латинская `A` вместо кириллической) проверку выхода из
  роли по-прежнему обманывает. Нормализация гомоглифов — большой молоток,
  который ломает законный смешанный текст; оставлено сознательно.
- Обстрел шёл по протоколу и по HTTP. Слой TLS, продление сертификата и всё,
  что ниже приложения, не проверялось ничем.
- Проверка «модель не двигает движок» сделана подстановкой самого выгодного
  ВАЛИДНОГО вердикта. Она ничего не говорит о вердикте, который не проходит
  валидацию, — такой отбрасывается целиком, и это отдельное свойство.
