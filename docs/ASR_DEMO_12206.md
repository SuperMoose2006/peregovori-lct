## Фактическое решение

Решил так, можно переиграть: основной ASR демо — **локальный Parakeet**
`nvidia/parakeet-tdt-0.6b-v3`. Он уже установлен на стенде отдельной службой,
пережил настоящий reboot и распознал контрольную запись. Gateway не загружает
модель в свои 2 ГБ памяти. Запасной путь при его отказе — **текстовый ввод**.
Автоматической отправки записи другому провайдеру в новом коде нет.

Выбор собран в `app/providers/asr/__init__.py`, используется endpoint и health:

| Настройка | Значение / поведение |
|---|---|
| `NEGO_VOICE` | default `classic`; только явное `realtime` выбирает OpenAI Realtime |
| `NEGO_ASR` | default `parakeet`; старое `auto` тоже означает только Parakeet |
| `NEGO_ASR_URL` | default `http://127.0.0.1:8020` |
| `NEGO_ASR_TIMEOUT_S` | default 20 секунд на HTTP-операцию |
| `NEGO_ASR=openrouter` | явное разрешение облачного распознавания |
| `NEGO_MODEL_ASR` | модель только OpenRouter, не переключатель провайдера |
| неизвестное значение | вход ASR выключен; автоматического fallback нет |

Наличие облачного ключа само по себе не меняет получателя аудио. `available()`
Parakeet означает наличие адреса, **не успешную health-пробу**: при временном
отказе сохраняется тот же провайдер, следующую реплику можно повторить.
`health.voice` и `capabilities.asr` называют конфигурацию, а ошибка запроса
публикует RU/EN сообщение «ход не отправлен, повторите или введите текст».
Очищаются аудио и старая промежуточная расшифровка; ход движка не происходит.
Если ASR выключен настройками, браузер не открывает микрофон, сохраняя TTS.

**Граница внедрения:** изменён только worktree. На стенде остался релиз
`20260920-04`, явно `NEGO_VOICE=classic`, `NEGO_ASR=parakeet`; его старый код
умеет уходить в облако при недоступном локальном ASR. Этот риск на установленном
релизе не объявлен устранённым. Нужен согласованный выпуск новой ветки перед
демо; публикация и переключение релиза ночью запрещены и не выполнялись.

## Один непрерывный прогон на настоящих зависимостях

Локальный новый gateway → SSH-туннель → настоящий Parakeet стенда; реальные
opponent `google/gemini-3.5-flash-lite`, judge `google/gemini-2.5-flash-lite`,
TTS `gpt-4o-mini-tts`. Эти имена дополнительно сверены с `/api/health` стенда.
Ключи считаны только в память процесса, не записаны и не выведены. На стенде
ничего не менялось. Browser — headless Chrome с записанным микрофоном, настоящие
AudioWorklet/WS/ASR; затем два текстовых хода через действия приложения.
Синтетических нажатий и ввода в окна не было. Физический микрофон не проверялся.

Итого **22,411 с**, JavaScript page errors: 0. Низкая оценка закономерна для
быстрого согласия на цену оппонента; тест не подменяет её на высокий балл.
12,493 с включает проигрывание записи и VAD, это **не** чистая задержка ASR.
Аттестация отключена, подписанный документ этот тренировочный прогон не выдаёт.
Финальный screenshot `06-debrief.png` просмотрен. Начальные screenshots были
перезаписаны следующей диагностической попыткой; времена полного прогона брать
из JSON, не собирать из снимков разных попыток.

**Голосовая приёмка не пройдена:** измеренная амплитуда браузерного проигрывателя
в полном приложении осталась нулевой. Первый прогон показал явный отказ TTS:
локальный Python не доверял системному TLS-сертификату. С CA из уже доверенного
macOS System.keychain и certifi проверка TLS прошла; отдельный запрос TTS вернул
8192 байта PCM. Проверка сертификата никогда не отключалась. Следующий полный
прогон дошёл до разбора, но слишком рано перебивал синтез. Последняя попытка
с ожиданием первого звука до 25 секунд также его не подтвердила. После трёх
неуспешных попыток по звуку дальнейшие подходы прекращены согласно рамке.
Не утверждаю ни исправность полного голосового демо, ни отказ самого TTS API:
отдельный API работает, связь с проигрывателем полного приложения ещё нужно
диагностировать. Не покупать другой сервис для обхода этого неизвестного.

Во время первого отказа найден отдельный дефект: notice TTS освобождал `busy`
до конца текстового потока. Исправлено адресно: `tts_unavailable` сохраняет
ожидание ответа; обычная ошибка ASR оставляет возможность нового ввода.

## Проверки и воспроизведение

Новые тесты `test_asr_selection.py` проверяют выбор по умолчанию при наличии
облачных ключей, явный opt-in, реальную сборку `_wire` и health, PCM float32 LE
16 кГц, отказ соединения без облачного вызова и без старого хода, RU/EN сообщение,
отсутствие неявного fallback из realtime. Frontend проверяет видимый провайдер,
запрет неработающего микрофона при сохранении TTS и ожидание текстового потока.

Семь новых мутаций: подмена фабрики, обход фабрики в endpoint, молчаливый отказ,
сохранение старой расшифровки, открытие запрещённого микрофона, неверная подпись
провайдера, преждевременное освобождение хода после TTS. Запуск:
`services/gateway/tools/check_resumed_mutations.py` с именами `asr-*` из файла
и `tts-premature-turn`. Файлы восстанавливаются в `finally`.

Финальная регрессия: **2752 passed, 159 skipped**, два предупреждения зависимостей,
35,76 с; **447 frontend passed**, 15,52 с; production build прошёл, Vite 873 мс.
Все семь новых мутаций пойманы, исходные файлы восстановлены. Логи лежат в
ignored `tmp/asr-backend-tests.log`, `tmp/asr-frontend-tests.log`,
`tmp/asr-build.log`, `tmp/resumed-mutations/`.

Повторный связанный браузерный fault-прогон на финальных файлах прошёл:
распознанная контрольная реплика → обрыв после применения хода → восстановление
того же хода за 364 мс → зависшая модель и текстовый fallback за 15,017 с →
соглашение/разбор. Затем экзамен и временный проверяемый документ за 2,553 с,
постоянный обрыв показал панель восстановления. Здесь ASR/LLM **управляемые
тестовые реализации**, это проверка отказов, не замена живой голосовой приёмки.
Ожидаемые ECONNRESET внесены TCP-прокси намеренно. Лог:
`tmp/asr-failures-browser.log`. Временный реестр удалён при остановке fixture.
