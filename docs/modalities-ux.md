# Мультимодальность: UX/UI — что куда садится

Продолжение `modalities.md`. Там решалось, куда сигнал имеет право попадать
логически; здесь — куда он садится **на экране**, в уже собранной оболочке
(сайдбар 256px · полоса статов · контент · приборный рельс · подвал).

---

## 0. Правило раскладки, парallельное правилу оценки

В `modalities.md` правило было: сигнал модальности не входит в оценку.
Его интерфейсный двойник:

> **Интерфейс не должен перестраиваться от того, включён доп или нет.**

Если камера двигает колонки, человек без камеры видит «урезанный продукт», а
демо превращается в рассказ про допы вместо рассказа про переговоры. Значит допы
занимают **заранее отведённые сворачиваемые слоты**, а не новые области.

Практически: слот существует всегда, в выключенном состоянии он схлопнут в
одну строку и читается как нормальный выбор, а не как поломка.

---

## 1. Где выбираются допы: экран перед партией

Сейчас клик по карточке сценария сразу бросает в переговоры. Предлагаю вставить
**один экран-подготовку** — он же решает проблему «как показать, что допы
опциональны».

```
┌─────────────────────────────────────────────────────────────┐
│  📦  КОНТРАКТ С ПОСТАВЩИКОМ                                 │
│  Вы — менеджер по закупкам. Напротив — Ирина, глава продаж. │
│  Цель ≤86 ₽ · красная линия 92 ₽ · 12 ходов                 │
│                                                             │
│  СЛОИ                                        [i] что это    │
│  ┌───────────────┐ ┌───────────────┐ ┌───────────────┐      │
│  │ 🎭 Читай лицо │ │ 🎤 Голосом    │ │ 📷 Камера     │      │
│  │ ○ выкл        │ │ ○ выкл        │ │ ○ недоступна  │      │
│  │ оценка та же  │ │ оценка та же  │ │ нет доступа   │      │
│  └───────────────┘ └───────────────┘ └───────────────┘      │
│                                                             │
│  Пресеты:  [ Классика ]  [ Читай лицо ]  [ Полный контакт ] │
│                                                             │
│                              ┌────────────────────────────┐ │
│                              │  НАЧАТЬ ПЕРЕГОВОРЫ         │ │
│                              └────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

Три решения внутри этого экрана:

**Слои, а не режимы.** Первый порыв — сделать «Читай лицо» пятым пунктом
сайдбара рядом с практикой/кампанией/экзаменом. Это неверно: режимы **не
складываются**, а слои складываются — голос вместе с чтением эмоций совершенно
осмысленная комбинация, и именно она ближе всего к настоящим переговорам.
Пять режимов вместо четырёх ещё и разбавляют навигацию.

**Пресеты сверху слоёв.** Жюри нужно название, которое можно произнести со сцены.
«Читай лицо» — это просто пресет, включающий один тумблер. Так у нас и
называемая сущность для демо, и композируемость.

**Подпись «оценка та же» прямо на тумблере.** Это не мелочь: она снимает главный
вопрос («а с камерой оценят строже?») в тот момент, когда он возникает, а не в
разборе. И честно отражает архитектуру.

Выключенный и недоступный — **визуально разные** состояния. Выключенный —
нормальный выбор. Недоступный — серый, с причиной («нет доступа», «нет
микрофона»), и по клику объясняет, как включить.

## 2. «Читай лицо»: вопрос в потоке, а не модалка

Ответ зависит от того, что игрок видит на экране: мимика аватара + движение
счётчиков + сама реплика. Модалка всё это **закрывает** — значит модалка
исключена. Вопрос садится в ленту диалога, ровно туда, где сейчас появляется
строка тренера.

```
   ┌──────────────────────────────────────┐
   │ Хорошо, но 92 — это наш потолок.     │   ← реплика оппонента
   └──────────────────────────────────────┘

   ╔══════════════════════════════════════════════════════╗
   ║ 🎭  ЧТО С НЕЙ СЕЙЧАС?                                ║
   ║                                                      ║
   ║  ┌────────────────┐  ┌────────────────┐              ║
   ║  │ Закрылась      │  │ Готова двигать │              ║
   ║  └────────────────┘  └────────────────┘              ║
   ║  ┌────────────────┐  ┌────────────────┐              ║
   ║  │ Под давлением  │  │ Потеплела      │              ║
   ║  └────────────────┘  └────────────────┘              ║
   ╚══════════════════════════════════════════════════════╝

   [ композер заблокирован до ответа ]
```

- **Аватар в этот момент укрупняется** (92 → ~160px) с плавным переходом — «камера
  наезжает на лицо». Это единственный момент, когда портрет становится главным
  объектом экрана, и он же оправдывает всю работу, вложенную в параметрическую
  мимику.
- **Счётчики остаются видны** — по ним и надо читать. Прятать их значит
  превратить упражнение в угадайку.
- **Обратная связь мгновенная и с причиной**: не «неверно», а «напряжение
  выросло на 12 — она закрылась, а не потеплела». Ошибка должна учить.
- Композер блокируется, но **лента не блокируется** — прокрутить назад и
  перечитать разрешено. Это чтение, а не тест на память.

## 3. Камера: самое важное решение — НЕ показывать своё лицо

Инстинктивное решение — большое самопревью, как в зуме. Оно вредно:
**человек, видящий себя, начинает следить за собой**, и меняется ровно то
поведение, которое мы измеряем. Плюс это отвлекает от собеседника — то есть
тренирует навык, обратный нужному.

Поэтому: по умолчанию **не превью, а индикатор кадрирования**.

```
 полоса статов:   🔥 3   💎 240 XP        [ 🎤 ] [ 📷 ● ] [ RU EN ] [ ◐ ] [ 🔊 ]
                                                   ▲
                                    зелёная точка = лицо в кадре
                                    жёлтая        = ушли из кадра
                                    серая         = выключено
```

- Одна точка в полосе статов, всегда на месте. **Состояние записи видно всегда** —
  это вопрос доверия, а не украшение.
- Полное самопревью — по клику на точку, всплывает в углу, закрывается тем же
  кликом. Для проверки света перед стартом, а не для сопровождения партии.
- В разборе — **лента сигналов под стенограммой**, выровненная по ходам:

```
  ход   1    2    3    4    5    6
  ────────────────────────────────────
  взгляд ▁▁▁ ▁▁▁ ▁▁▁ ███ ▁▁▁ ▁▁▁     ← отвели глаза на ходу 4
  пауза  2с   4с   3с  47с   5с   3с
                       ▲
        «вы назвали цену — и посмотрели вниз»
```

Формулировка привязана к ходу и цитирует реплику. Не «вы нервничали» (диагноз
личности), а «на этой реплике вы отвели взгляд» (наблюдение о моменте).

Карточка помечена бейджем **«наблюдение · не влияет на оценку»** — тем же
визуальным маркером, что и все остальные негрейдовые блоки.

## 4. Голос: композер превращается в микрофон

Голос не добавляет новую область — он **переключает состояние композера**.

```
 текст:  ┌────────────────────────────────────────┐ ┌───┐
         │ Ваша реплика своими словами…           │ │ ▶ │
         └────────────────────────────────────────┘ └───┘
         [⌨/🎤]  ❓Вопрос SPIN  🎯Интерес  📊Критерий …

 голос:  ┌────────────────────────────────────────┐ ┌───┐
         │ «по рынку это идёт восемьдесят шесть…» │ │ ▶ │   ← живая расшифровка
         └────────────────────────────────────────┘ └───┘
         [⌨/🎤]  ●━━━━━━━━━━  держите, чтобы говорить
```

**Критическая деталь:** расшифровка показывается **до отправки** и остаётся
редактируемой. Иначе ослышка распознавания молча становится вашим ходом, и движок
судит её как ваши слова. Это ровно тот же инвариант, что уже соблюдает подсказка
коуча: реплику вставляет система, но отправляет всегда игрок.

Ответ оппонента: индикатор «печатает…» становится «говорит…», **но пузырь с
текстом остаётся**. Текст — это и запись партии, и доступность, и шумный зал.
Голос дополняет ленту, а не заменяет её.

**Время ответа в обычной игре не показывается.** Видимый таймер — это давление,
которого нет в задании; он изменит поведение и испортит замер. Время пишется
молча и всплывает только в разборе. Исключение — пресет «Блиц», где таймер и есть
правило, и тогда он крупный и честный.

## 5. Разбор: где живут негрейдовые блоки

Разбор уже устроен как документ: кольцо грейда → три шкалы → занавес интересов →
статы → ключевые ходы → слово наставника. Слои дают **по одной карточке каждый**,
и все они идут **ниже статов**, в зоне «объяснения», а не в зоне «оценки».

```
  ┌─ КОЛЬЦО ГРЕЙДА + ТРИ ШКАЛЫ ────────────┐  ← оценка. сюда допы не лезут
  └────────────────────────────────────────┘
  ┌─ 🔎 занавес интересов ──────────────────┐
  ┌─ 🎭 как вы читали её  · наблюдение ─────┐  ← слой «Читай лицо»
  ┌─ 📷 как вы держались   · наблюдение ────┐  ← слой «Камера»
  ┌─ ⏱ где вы думали дольше · наблюдение ──┐  ← время ответа
  ┌─ ⚡ ключевые ходы ──────────────────────┐
  ┌─ 🎓 слово наставника ───────────────────┐
```

Общий маркер «наблюдение» на всех негрейдовых карточках — одна и та же плашка,
один и тот же цвет. Тогда граница «что оценено / что просто замечено» читается
без чтения текста.

## 6. Что это меняет в оболочке

Ничего структурно. Проверка по областям:

| Область | Изменение |
|---|---|
| Сайдбар | без изменений — слои не режимы, новых пунктов нет |
| Полоса статов | + два тумблера состояния (🎤 / 📷), всегда на месте |
| Контент | + экран подготовки перед партией |
| Лента диалога | + карточка вопроса (там же, где строка тренера) |
| Композер | + переключатель ⌨/🎤, состояние «говорит» |
| Приборный рельс | без изменений |
| Разбор | + до трёх карточек в зоне объяснения |
| Подвал | без изменений |

Ни одна новая колонка, ни одна новая область экрана. Это и есть проверка, что
«можно без допов» — правда: выключите всё, и раскладка та же самая.

## 7. Открытые вопросы дизайна

1. **Экран подготовки на каждый запуск?** Для повторной партии он лишний клик.
   Вариант: показывать один раз на сценарий, дальше — свернутая строка «Слои:
   классика · изменить».
2. **Укрупнение аватара при вопросе** — насколько сильно двигать раскладку?
   Резкий скачок 92 → 160px может дёрнуть ленту. Возможно, укрупнять поверх, а не
   в потоке.
3. **Пресет «Полный контакт»** (голос + камера + чтение) — это лучший кадр для
   защиты, но и самый хрупкий на площадке. Стоит ли делать его пресетом по
   умолчанию для демо-режима или оставить ручным.
