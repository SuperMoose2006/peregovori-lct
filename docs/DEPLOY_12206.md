## Приёмка на установленном backend

`frontend/e2e/stand-passive.mjs` использует настоящий сервер через SSH-туннель
на его порт 8010. UI загружается из совпадающих исходников worktree через Vite,
с тестовым доступом к действиям приложения. Отдельно проверено соответствие
раздаваемого production index релизу. Мышь, клавиши и DOM input events не
имитировались; микрофон — записанный WAV через Chrome getUserMedia/AudioWorklet.

1. Первый установленный релиз `b73a35e`: записанная фраза распознана настоящим
   Parakeet, три хода и разбор за **28,406 с**. В браузер пришло **378** аудиочанков,
   максимальный RMS **0,3391**, но прибор приложения показал ноль.
2. Найдена конкретная причина: `createTransport` передавал `micLevel()`, но не
   передавал `speechLevel()`. В полном приложении метод отсутствовал, и hook
   возвращал 0. Исправлена **одна строка проксирования**, не аудиодвижок.
   Browser-тест `transport-level-passive.mjs` проверяет 0 до загрузки, затем
   живые 0,35 и 0,72. Мутация «всегда 0» краснеет (`speech-proxy: CAUGHT`).
3. На установленном backend реально остановлен только `dialog-asr`. Заранее
   поставлен временный страховочный запуск через 90 с; постоянные unit-файлы
   не менялись. На **9,651 с** браузер показал «Распознавание недоступно»;
   ход остался **0**, расшифрованной реплики нет, автоматическое облако не
   включилось. Тот же стол принял текст, стал ходом 1 на **11,301 с** и дошёл
   до разбора на **17,196 с**. Сервер прислал `asr_unavailable`.
4. ASR запущен обратно; health: ok, модель Parakeet, **load_seconds=25.4**,
   threads=6. Страховочный таймер уже отработал и выгрузился; повторный stop
   таймера сообщил «not loaded», работающий ASR это не остановило.
5. После финального релиза `01180e4` и запуска ASR: стол на **2,269 с**,
   распознанный голосовой ход с ответом на **13,293 с**, финальный разбор
   на **28,524 с**, весь прибор **28,564 с**. **376** аудиочанков, RMS **0,2896**,
   измеренная амплитуда воспроизведения **1**, ошибок JS **0**, итог C.
   Это положительная проверка записи → Parakeet → серверный ход → TTS PCM →
   работающий AudioContext/амплитуда приложения после перезапуска службы.

Backend между двумя релизами одинаков; проверка отказа ASR применима и к
финальному релизу. Отдельного reboot хоста не делали; его прежняя проверка
сохраняется в RESUMED_12206.md. После выкатки проверен именно stop/start ASR и
restart gateway. Финальные состояния обеих служб active/running, NRestarts=0.
Постоянная аттестация **выключена**: endpoint реестра отвечает 503 «not configured».

Логи/снимки: `tmp/stand-rehearsal/{recording,asr-down}/result.json` и PNG.
