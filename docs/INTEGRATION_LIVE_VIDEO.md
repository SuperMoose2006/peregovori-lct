# Живое видео собеседника: что сделать, когда придут креды

Документ для того, кто получил ключ платного сервиса видео и хочет, чтобы
оппонент на экране стал живым лицом, а не рисованным портретом. Написан
29.09.2026, ветка `feature/live-video-adapter` от `747a494`.

## Коротко

- **Без ключа ничего не меняется.** Рисованный портрет, рот по громкости, ни
  одного нового события по сокету, ни одной строки в консоли браузера. Так
  идёт сдача. Проверено браузером (раздел 7).
- **С ключом — две строки в окружении и перезапуск.** Имя сервиса
  (`NEGO_LIVE_VIDEO`) и его ключ (`NEGO_LIVE_VIDEO_KEY`). Если имя сервиса и
  SDK поставлены заранее (раздел 1), после ключа остаётся ровно одна строка.
- **Готово три драйвера:** Anam, HeyGen LiveAvatar (режим LITE), Simli — плюс
  заглушка `stub` без сети. Выбор сервиса — не здесь: слой подходит любому,
  кто рисует лицо под наш звук.
- **Ни один платный сервис вживую не проверен: ключа нет.** Драйверы написаны
  по исходникам SDK и публичной документации и проверены против подменённого
  сервиса. Первая живая сессия — шаг 5 ниже; что может не сойтись — раздел 5.
- **Если сервис отвалился посреди переговоров** — лицо сразу возвращается к
  рисованному портрету, голос и партия идут дальше. Между репликами слой сам
  пробует вернуть видео. Это проверено сценарием показа в браузере.

## 1. До ключа — можно сделать сегодня, бесплатно

| Шаг | Кто | Время (оценка) | Команда |
|---|---|---|---|
| Назвать сервис | тот, кто выбрал | 1 мин | в `services/gateway/.env` (стенд — `/etc/dialog.env`): `NEGO_LIVE_VIDEO=liveavatar` (или `anam`, `simli`) |
| Поставить SDK сервисов | тот, кто выкатывает | 2–4 мин | `make live-video-install` (ниже — для стенда) |
| Прогнать путь заглушкой | любой | 3 мин | ниже, «Заглушка» |

Пока ключа нет, названный сервис спокойно выключен: `/api/health` отвечает
`live_video: "off: нет ключа NEGO_LIVE_VIDEO_KEY (liveavatar)"`, в логе одна
строка уровня INFO, для человека — прежний портрет.

**SDK на стенде** — тем же `uv`, что и основные зависимости (`deploy/README.md`,
«Обновление», шаг 4), после установки основного набора:

```bash
/opt/dialog/tooling/bin/uv pip install \
  --python /opt/dialog/releases/ID/services/gateway/.venv/bin/python \
  -r /opt/dialog/releases/ID/services/gateway/requirements-live-video.txt
```

Внимание: `aiortc` (нужен Anam и Simli) требует `av` младше 18, и установка
опускает `av` с 18.1.0 до 17.1.0. Весь набор тестов шлюза проверен на 17.1.0 —
зелёный. Если выбран LiveAvatar, достаточно одного пакета, и `av` он не
трогает:

```bash
services/gateway/.venv/bin/pip install livekit==1.1.20
```

Файл `requirements-live-video.txt` едет в артефакт выкладки
(`pack_backend.sh`).

Я этого на стенде НЕ делала: выкладка на стенд в этой работе запрещена.
Локально SDK стоят в `services/gateway/.venv`, и тесты сверяют драйверы с
настоящими классами пакетов.

**Заглушка — весь путь без денег и без сети.** Кадры синтетические (портрет с
надписью STUB и бегущей меткой времени), интерфейс подписывает их «тестовый
видеопоток». Годится и для репетиции показа: обрыв сервиса по заказу.

```bash
cd services/gateway && NEGO_LIVE_VIDEO=stub .venv/bin/python -m tools.live_video_check --session
NEGO_LIVE_VIDEO=stub NEGO_LIVE_VIDEO_STUB_FAIL_AFTER_S=40 make gateway
```

Вторая строка поднимает шлюз, у которого «сервис» отваливается через 40 секунд
после начала партии: видно, как лицо возвращается к портрету, а партия идёт
дальше. Для браузерной проверки обоих режимов — `frontend/e2e/live-video.mjs`
(команды в шапке файла).

## 2. Когда пришёл ключ — по шагам

Время — оценка, не замер. Команды — из корня репозитория, если не сказано иное.

**Шаг 1. Вписать ключ — 1 минута.** В `services/gateway/.env` (на стенде —
`/etc/dialog.env`, root, режим 0600):

```bash
NEGO_LIVE_VIDEO=liveavatar
NEGO_LIVE_VIDEO_KEY=вставить_ключ_без_кавычек_и_пробелов
```

Лицо (`NEGO_LIVE_VIDEO_AVATAR`) можно не задавать: Anam и LiveAvatar берут
первое стоковое лицо своего каталога и пишут в лог, какое взяли. Simli
стокового каталога не имеет — ему id лица обязателен, без него шлюз скажет об
этом при старте.

**Шаг 2 (только LiveAvatar, по желанию) — бесплатная песочница, 1 минута.**
`NEGO_LIVE_VIDEO_SANDBOX=1`: сессия около минуты, тестовое лицо сервиса,
кредиты не списываются (по документации сервиса). Удобно для шага 5, чтобы
первая проверка ничего не стоила. После проверки — убрать строку.

**Шаг 3. Бесплатная проверка ключа — 10 секунд.**

```bash
make live-video-check
```

Что печатает при удаче (LiveAvatar). Это ФОРМАТ вывода, собранный по коду
прибора, а не прогон: с настоящим ключом прибор не запускался, число кредитов
условное.

```
сервис: liveavatar; вход: audio; лицо: по умолчанию сервиса
итог настроек: liveavatar: ключ принят — кредитов осталось: 1100
/api/health скажет: live_video = 'liveavatar (видео собеседника; вход audio, голос наш)'
сессию не открывали (бесплатный режим). Живая проверка: --session
```

Без флагов прибор не открывает ни одной сессии: для Anam это каталог лиц, для
LiveAvatar — остаток кредитов, для Simli — запрос ICE-серверов. Битый ключ
здесь же называется словами (раздел 5).

**Шаг 4. Перезапустить шлюз — до минуты.** Локально: остановить и снова
`make gateway`. Стенд: `sudo systemctl restart dialog` (шлюз ждёт готовности
распознавания — это и есть «до минуты»). Ключ проверяется ещё раз при старте;
итог — строкой в журнале: `journalctl -u dialog | grep "живое видео"`.

**Шаг 5. Одна короткая живая сессия — 1 минута, около 0.5 минуты тарифа.**

```bash
make live-video-check ARGS="--session --save /tmp/lv-frames"
```

Прибор открывает настоящую сессию, подаёт в тот же адаптер, что в партии, три
секунды синтетической речи и печатает: за сколько подключились, сколько кадров
пришло, опоздало и прорежено, на сколько кадр отстаёт от своего звука (p50 и
p95) и какое удержание звука из этого следует. Пять-шесть кадров JPEG кладёт в
`/tmp/lv-frames` — открыть и посмотреть глазами, что это лицо, а не чёрный
квадрат. Итог — `✓ живое видео работает` или список того, что не сошлось.

Так выглядит вывод на заглушке (замер 29.09, задержка заглушки 250 мс):

```
✓ подключились за 0.10 с
  звук: 30/30 кусков ушло человеку (придержано 30, сразу 0)
  кадры: пришло 75, отдано 38, опоздало 0, прорежено 37, чужих 0, битых 0
  отставание кадра от своего звука: p50 254 мс, p95 261 мс
  удержание звука сейчас 350 мс; по замеру нужно ≈ 150 мс (NEGO_LIVE_VIDEO_AV_DELAY_MS=150)
✓ живое видео работает
```

**Шаг 6. Подобрать удержание звука — 2 минуты.** Если прибор советует число,
заметно отличное от текущего, — вписать его и перезапустить:
`NEGO_LIVE_VIDEO_AV_DELAY_MS=<число из вывода>`. Меньше — голос раньше, но
кадры опаздывают; больше — губы успевают, но первый звук позже на столько же.

**Шаг 7. Партия в браузере — 2 минуты.** Раздел 3.

Итого после ключа, если шаги раздела 1 сделаны заранее: строка ключа,
перезапуск и две минуты проверки. Шаги 5–6 — настройка, а не условие работы:
без них видео включено с удержанием по заявлению вендора.

## 3. Как проверить за две минуты, что заработало

1. `curl -s http://127.0.0.1:8010/api/health` — поле `live_video` называет
   сервис, а не `off: …`.
2. В браузере: «Тренировка», слои «Голосом» и «Лицо оппонента», любой стол.
   Открывается встреча с крупным собеседником.
3. Сказать или написать реплику. Пока оппонент говорит, лицо — видео сервиса:
   губы двигаются в такт голосу, подписи «тестовый видеопоток» нет (она есть
   только у заглушки).
4. Нажать «Перебить», пока он говорит: замолкают и голос, и лицо.
5. Между репликами лицо — портрет того же персонажа (так задумано: кадры идут
   только под звук, раздел 5).

Если на шаге 3 лицо рисованное, в журнале шлюза есть строка
`живое видео: … — лицо вернулось к портрету (<причина>, …)` — по ней раздел 5.

## 4. Как выключить одной строкой

```bash
NEGO_LIVE_VIDEO=off
```

и перезапуск шлюза. Всё — как без этого слоя: рисованный портрет, звук без
удержания. Ключ можно не стирать. Выключить посреди показа без перезапуска
нельзя, но и не нужно: при любом отказе сервиса партия сама возвращается к
портрету.

## 5. Что может не сойтись и как это будет выглядеть

Во всех случаях ниже голос и партия продолжаются: отказ лица голос не теряет
(придержанный звук уходит человеку сразу и по порядку) и ход не ломает.

| Что | Как выглядит | Что делать |
|---|---|---|
| Ключ с пробелом, в кавычках, кириллицей, заглушка `...`, ключ OpenRouter не в той строке | при старте в журнале: `живое видео выключено: NEGO_LIVE_VIDEO_KEY: …` словами; health `off: …`; портрет | вставить ключ заново |
| Сервис отверг ключ (401/403) или нет тарифа (402) | при старте: `живое видео выключено: … отверг ключ …`; портрет до перезапуска | проверить ключ в кабинете сервиса |
| SDK не поставлен | health `off: для anam не установлены модули: … — pip install -r …` | `make live-video-install` |
| Кончились минуты посреди партии | сервис закрывает сессию — портрет; одна попытка переподключиться получает отказ тарифа (402 / `usage_limit_reached`), дальше без повторов до конца партии | пополнить тариф |
| Сервис не на связи к первой реплике (медленное подключение) | эта реплика — с рисованным портретом; следующая — видео | ничего; отказом не считается |
| Кадры опаздывают больше окна | каждый опоздавший кадр отброшен (к клиенту старше 250 мс не уходит), лицо отстаёт от голоса дольше 1.5 с речи — портрет; следующая реплика пробует снова | шаг 5–6: поднять `NEGO_LIVE_VIDEO_AV_DELAY_MS` |
| Губы стабильно спешат или отстают на глаз | видео есть, но рассинхрон постоянный | `NEGO_LIVE_VIDEO_PTS_OFFSET_MS`: +N сдвигает кадры позже, −N раньше |
| Сервис закрыл сессию по лимиту длины (Anam Starter — 5 мин, LiveAvatar Essential — 20 мин, по документации) | посреди партии — портрет, через 1–8 с переподключение, видео возвращается со следующей реплики | ничего; до трёх отказов за партию |
| Три отказа за партию | портрет до конца этой партии, сессия у сервиса закрыта | смотреть журнал; следующая партия начинает заново |
| Лимит одновременных сессий (Anam Starter — одна) | вторая параллельная партия — портрет | тариф выше или одна партия за раз |
| Доступ или оплата из России | подключение не проходит — портрет | сервер выкладки вне РФ; раздел «Россия» в `docs/research/video-avatar-providers.md` |
| LiveAvatar: у `livekit_agent_token` нет прав на подписку (в документации права не описаны) | в журнале `лицо не опубликовало видео и звук в комнате` — портрет | правка в одну строку в `vendors/liveavatar.py`: брать `livekit_client_token` первым |
| Лицо сервиса не похоже на нашего персонажа | стоковое лицо одно на все 15 персонажей | свои лица у сервиса (платно, слоты по тарифу) и `NEGO_LIVE_VIDEO_AVATAR` |

**Цена ожидания.** Удержание звука добавляется к первому звуку каждой
реплики: у Anam и LiveAvatar по умолчанию 600 мс, у Simli 450 мс — это оценки
по заявлениям вендоров, не замер. Шаг 5 даёт настоящее число.

**Трафик.** Кадры идут по сокету партии JPEG-ами: 15 кадров в секунду по
20–30 КБ — порядка 3–4 Мбит/с на партию во время речи (оценка). Между
репликами кадров нет. Снизить: `NEGO_LIVE_VIDEO_FPS=10`, `NEGO_LIVE_VIDEO_SIZE=256`.

**Стоимость.** Сервисы считают минуты сессии от подключения до закрытия,
включая молчание. Сессия открывается при сборке партии и закрывается с ней;
LiveAvatar при закрытии останавливается явным запросом. Партия в 10–15 минут —
10–15 минут тарифа.

## 6. Наш звук или их голос: что меняется

Сервисы бывают двух видов, и слой поддерживает оба (`DriverInfo.input`,
`NEGO_LIVE_VIDEO_INPUT`). Все три готовых драйвера — первого вида; второй
проверен заглушкой.

| | `audio` — сервис рисует лицо под НАШ звук | `text` — сервис говорит САМ |
|---|---|---|
| Кто озвучивает | наш синтез, как сейчас (`gpt-4o-mini-tts` или edge) | синтез сервиса, его голосом |
| Голос персонажа | тот же, что без видео; пол — из сценария | голос, выбранный у сервиса; наш выбор по полу не действует |
| Русская речь | не зависит от сервиса | зависит от синтеза сервиса — проверять ухом |
| Задержка до первого звука | наш синтез + удержание звука под кадры | синтез сервиса + его видео, последовательно; наш замер синтеза к ней неприменим |
| Защита «не выходить из роли» | как сейчас: фраза проверяется ДО озвучки | та же: в сервис уходит только уже проверенный текст фразы |
| Кто решает, что сказать | движок; сервис только рисует | движок; сервису запрещено отвечать самому (без его «мозга») |
| Отказ сервиса | лицо → портрет, голос не прерывается; между репликами видео возвращается | отказ лица — это и отказ голоса: оборванная фраза звучит заново нашим синтезом, и дальше до конца партии голос наш, лицо — портрет (голос не прыгает туда-обратно) |
| Потолок ожидания фразы | наш: 15 с на фразу | сервис говорит в реальном времени, фразы ждут очереди — потолок 120 с, молчание ловит сторож |
| Готовые драйверы | Anam, LiveAvatar LITE, Simli | только заглушка (`NEGO_LIVE_VIDEO=stub`, `NEGO_LIVE_VIDEO_INPUT=text`) |

Рекомендация — `audio`: голос, его задержка и защита остаются нашими, а отказ
сервиса не трогает голос. `text` имеет смысл, только если выбранный сервис не
умеет принимать звук.

## 7. Что сделано и чем проверено

**Устройство.** Пакет `services/gateway/app/avatar/live/`:

- `driver.py` — узкий интерфейс сервиса: подключиться, звук или текст, кадры,
  замолчать, закрыться; обрыв — событием `Closed`;
- `adapter.py` — всё, что от сервиса не зависит: удержание звука под кадры
  (замечание R1 ревью), сигнал конца звука (R2), сторож молчания и опоздания,
  возврат портрета без потери голоса, возврат видео между репликами,
  переподключение, предел отказов;
- `clock.py` — оценка на сервере, когда у клиента звучит каждая миллисекунда
  реплики (повторяет джиттер-буфер проигрывателя);
- `voice.py` — вход `text` с нашим синтезом в запасе;
- `config.py` — переменные, проверка ключа при старте, флаг по кредам;
- `stub.py` — заглушка с задержкой и обрывом по заказу;
- `vendors/` — Anam, LiveAvatar, Simli и общая часть WebRTC.

Бизнес-логика имени сервиса не знает: оркестратор и сборка партии говорят с
лицом через прежний `AvatarProvider` и три новых необязательных действия
(`audio_out`, `end_of_speech`, `voice_for`), у локальных лиц пустых.
Клиенту добавлено одно: событие `avatar.state` с `lipsync_mode: "video"`
возвращает лицо к кадрам после переподключения; при возврате к портрету
снимается подпись «тестовый видеопоток».

**Проверки** (все прогоны — 29.09.2026, в этом рабочем дереве):

- `tests/test_live_video.py` и `tests/test_live_video_vendors.py` — 75 тестов:
  флаг и ключ, часы клиента, порог 250 мс, обрыв посреди реплики, молчание
  сервиса дольше порога, опоздание кадров и спасение удержанием, возврат
  видео, переподключение, перебивание, закрытие, оба входа, проводка партии,
  экзамен без видео, одинаковый грейд с видео и без, три драйвера против
  подменённого сервиса и сверка с настоящими SDK.
- `frontend/test/liveVideo.test.ts` — 4 теста клиента.
- `frontend/e2e/live-video.mjs` — безголовый Chrome: без кредов (12 проверок:
  только рисованный портрет, ноль кадров по сокету, реплика пришла, ход закрыт,
  консоль чистая) и заглушка с обрывом посреди партии (13 проверок: кадры по
  звуку → обрыв → портрет без подписи тестового потока → следующая реплика
  звучит, следующий ход разрешён).
- Мутационная проверка — `tools/check_live_video_mutations.py`: 105
  намеренных поломок в одну-две строки (47 в слое, 33 в драйверах, 16 в
  проводке партии, 9 в клиенте); на каждой прогоняются все 104 проверки
  (75 + 4 + 12 + 13). Итог прогона 29.09: поймано 105 из 105, и каждая из
  104 проверок краснеет хотя бы на одной поломке. По дороге прибор нашёл
