# CLAUDE.md — правила и архитектура проекта «Диалог»

Тренажёр навыков переговоров для хакатона ЛЦТ (Лидеры цифровой трансформации, Москва).
Исход переговоров зависит от стратегии, формулировок и аргументов игрока.
Методики: Гарвардский метод · SPIN · BATNA.

---

## 🧭 Целевая архитектура

Разделённые **backend (Python)** и **frontend (React)**, общающиеся по модальностно-независимому
протоколу «ход» (turn). Текстовый чат сейчас, голосовой realtime потом — это разные адаптеры
ввода/вывода поверх одного и того же протокола.

```
┌──────────────────┐   WebSocket (REST fallback)   ┌────────────────────────────────┐
│ FRONTEND (React) │ ── turn {text} ─────────────► │ BACKEND (Python / FastAPI)     │
│  чат сейчас      │ ◄─ reply {text, state, ...} ─ │                                │
│  голос потом     │                               │  ├─ Движок (детерминированный):│
└──────────────────┘                               │  │   состояние, ZOPA, счёт     │
        ▲                                           │  │   = ЕДИНСТВЕННЫЙ источник    │
   STT/TTS позже                                    │  │     истины                  │
   (та же turn-абстракция,                          │  ├─ LangGraph: граф оппонента  │
    голос → text на входе,                          │  │      │                       │
    text → голос на выходе)                         │  │      ▼                       │
                                                    │  │   ChatModel (LangChain)      │
                                                    │  │   локально → claude CLI      │
                                                    │  │   прод → ChatAnthropic (API) │
                                                    └──┴────────────────────────────┘
```

---

## 🎯 Главный принцип (не нарушать)

**Состояние игры и оценку ВСЕГДА считает детерминированный движок. ИИ (LangGraph/ChatModel)
отвечает только за текст реплик оппонента.**

- Метрики (Доверие/Напряжение/Информация/Рычаг), движение цены в ZOPA, вскрытие интересов,
  финальный счёт и грейд — только движок. Никогда не отдавать это модели.
- LangGraph-нода получает факты состояния и возвращает 1–2 короткие реплики в характере.
  Ошибка/таймаут ИИ → шаблонный фолбэк из движка. Игра не должна ломаться без ИИ/сети.
- Причина: тренажёр обязан быть **прозрачным, честным и воспроизводимым**.

> ⚠️ Открытый вопрос (не решён): поднимать ли роль ИИ до «мозга оппонента» (B) или
> «ИИ-судьи аргументации» (C). До явного решения держим принцип выше (ИИ = голос).

## 🔌 Протокол «ход» (turn) — модальностно-независимый

Сердце архитектуры под будущий голос. Транспорт — **WebSocket-first**, REST как fallback.

**client → server**
- `{ "type": "start", "scenarioId": "...", "lang": "ru|en" }`
- `{ "type": "turn", "text": "реплика игрока" }`  ← голос позже даёт тот же `text` через STT

**server → client**
- `{ "type": "opponent", "text": "...", "analysis": {...}, "deltas": {...}, "state": {...} }`
- `{ "type": "opponent_delta", "chunk": "..." }`  ← стриминг токенов (и будущий TTS)
- `{ "type": "debrief", ... }` · `{ "type": "state", ... }` · `{ "type": "error", ... }`

Правило: **ядро протокола всегда текстовое**. Голос — это только адаптеры на краях
(STT на входе, TTS на выходе). Ничего в движке/графе не завязывать на модальность.

## 🤖 Слой ИИ

- ИИ подключается как **LangChain ChatModel** внутри LangGraph-графа. Выбор бэкенда — через env,
  граф при этом НЕ меняется.
- `NEGO_AI`:
  | значение | бэкенд | назначение |
  |---|---|---|
  | `off` | шаблонные реплики движка | офлайн-фолбэк, тесты |
  | `cli` (по умолч. локально) | обёртка над `claude` CLI (`claude -p`, `--effort low`) | разработка без API-ключа |
  | `sdk` | Claude Agent SDK (`claude-agent-sdk`, thinking off, `setting_sources=[]`) | «правильный» Claude-клиент по подписке; те же rate-limits |
  | `tmux` | `claude -p` в персистентной tmux-сессии (file-based, без TUI-скрейпинга) | наблюдаемый Claude: `tmux attach -t nego-ai`; латентность как у `cli` |
  | `api` | `ChatAnthropic` | продакшен (`ANTHROPIC_API_KEY`) |
  | `openai` | `ChatOpenAI` на любой OpenAI-совместимый эндпоинт | дешёвый прод; без `OPENAI_BASE_URL` — сам OpenAI (`gpt-5-nano`) |
  | `openai` + `OPENAI_BASE_URL=https://openrouter.ai/api/v1` | тот же ChatOpenAI через OpenRouter | **текущий рабочий профиль**: `mistralai/mistral-nemo` (~$0.02/$0.03 за M токенов), server-side fallback на резервные модели |
  - Секреты — в `backend/.env` (gitignored, автозагрузка в `main.py`), не в командной строке.
  - Модель: `NEGO_OPENAI_MODEL` > `NEGO_MODEL` (если он вообще servable этим эндпоинтом) > дефолт.
    Выбор модели обоснован живым бейк-оффом — `docs/model-bakeoff.md`. Дешёвые модели ломаются
    по-разному (чужой алфавит в реплике, судья не отличает спам от сути, перевёрнутый `dir`),
    поэтому в коде есть защиты: `_script_ok` (реплика с CJK → шаблонный фолбэк), закрытый словарь
    приёмов судьи, явная числовая рубрика в `judge.py`. **Тесты всегда офлайн** — `tests/conftest.py`
    принудительно ставит `NEGO_AI=off`, чтобы `.env` не утащил suite в сеть и в расходы.
- `claude_cli` ChatModel вызывает `claude -p --model <NEGO_MODEL> --output-format text` через
  subprocess. (Опционально — через tmux-сессию для наблюдения: `tmux attach -t nego-ai`.)
- `NEGO_MODEL` по умолчанию `claude-sonnet-5`; локально для скорости — `claude-haiku-4-5-20251001`.
- **Переход в прод = смена одной env** (`NEGO_AI=api`). tmux/CLI-специфику держать только внутри
  `claude_cli` ChatModel, наружу не протекать.

## 🧱 Стек и структура (монорепо)

```
backend/                      # Python 3.11+, FastAPI, LangGraph
  app/
    main.py                   # FastAPI: WS /ws, REST fallback, статика dev
    protocol.py               # Pydantic-схемы turn/reply/state (общий контракт)
    session.py                # хранилище сессий
    engine/                   # ДЕТЕРМИНИРОВАННЫЙ движок (порт с JS-прототипа)
      techniques.py           #   классификатор ходов + оценка аргументации (RU/EN)
      engine.py               #   конечный автомат, оппонент по персоне, счёт, разбор
      scenarios.py            #   сценарии: позиции, интересы, ZOPA, персоны
    ai/
      graph.py                # LangGraph граф оппонента
      chat_models.py          # ChatModel-обёртки: claude_cli | anthropic (по env)
      prompts.py              # системные промпты/факты состояния
  tests/
    test_engine.py            # поведенческие тесты (порт 14 инвариантов с JS)
  pyproject.toml

frontend/                     # React + Vite + TypeScript
  src/
    main.tsx, App.tsx
    api/ws.ts                 # WS-клиент поверх turn-протокола (+REST fallback)
    types.ts                  # типы протокола (зеркало protocol.py)
    i18n.ts                   # строки RU/EN
    components/               # ScenarioPicker, Table(Meters+Chat), Debrief
  package.json, vite.config.ts

legacy-node/                  # старый zero-dep прототип — как эталон поведения (не деплоится)
```

- Старый Node-прототип (`server.js`, `engine/*.js`, `public/*`) переезжает в `legacy-node/`
  и служит **эталоном поведения**: Python-движок должен давать те же результаты, тесты портируются.
- `public/demo.html` (Artifact) — оставить как самодостаточное демо-превью.

## 🧩 Ключевые инварианты (проверять при каждой правке движка)

1. Оппонент **никогда не переходит свой floor** (reservation price).
2. Принципиальная игра (вскрытие интересов → объективные критерии → размен) → грейд **A/B**;
   агрессия/грубость → **срыв / F**.
3. Оценка честная и объяснимая: `overall = 0.4·economic + 0.25·relationship + 0.35·technique`.
4. Билингвальность RU/EN во всём пользовательском контенте (`{ru, en}`).
5. Без ИИ/сети продукт полностью играбелен (шаблонный фолбэк).

## ✍️ Конвенции

- Комментарии объясняют **почему**, а не что. Плотность — как в соседнем коде.
- Типы протокола — единый контракт: `protocol.py` (Pydantic) ↔ `types.ts`. Менять синхронно.
- Правки движка → `pytest` зелёный + проверка баланса (см. инварианты).
- Новый сценарий = запись в `scenarios.py` с 3 скрытыми интересами и корректной ZOPA;
  проверить оба направления (`dir: low|high`).

## 🧰 Заметки окружения

- В этом харнессе **foreground `sleep` заблокирован** (bash падает с кодом 144). Не использовать
  `sleep`; долгоживущие процессы (uvicorn, vite) запускать через **Bash-инструмент с
  `run_in_background: true`** — обычный `&`/`setsid`/`nohup` харнесс убивает (exit 144).
- **Порт 8000 занят** другим контейнером (`queue_manager_service`) — бэкенд слушает **:8010**.
- **CLI-бэкенд ИИ (`claude -p`) изолируем от глобального окружения Claude Code** флагами
  `--setting-sources ""` (не грузить CLAUDE.md/скиллы/плагины/хуки; OAuth-креды лежат отдельно,
  авторизация сохраняется) + `--system-prompt <наш>` (заменяет дефолтный агентский промпт) +
  нейтральный cwd. Иначе он подхватывает глобальный superpowers-плагин и отвечает как «Claude Code»
  (классифицирует задачу как *Bounded* и т.п.), причём НЕДЕТЕРМИНИРОВАННО. С изоляцией — чисто и
  ~20–25с на генерацию сценария. См. `CliBackend.generate` в `ai/chat_models.py`.
  Всё равно медленно/локальный фолбэк; прод-путь (`NEGO_AI=api`, ChatAnthropic) — секунды.
- Блокирующие вызовы ИИ (CLI subprocess) в async-хендлере оборачивать в `asyncio.to_thread`,
  иначе долгая генерация (~25с) блокирует event loop и рвёт WebSocket. См. `main.py`.

## 🧠 Семантический судья (ИИ-судья, гибрид A+C)

`NEGO_JUDGE=1` (нужен ИИ-бэкенд) включает `ai/judge.py`: LLM оценивает аргументацию по СМЫСЛУ (а не
по ключевым словам), определяет, в какой из скрытых интересов реально метит вопрос, и даёт пер-ход
коучинг. Движок остаётся источником истины: `apply_move(judge=...)` заменяет keyword-arg на
семантический балл и раскрывает ИМЕННО тот интерес, что вскрыл вопрос (расплывчатый вопрос → ничего).
Выкл (по умолчанию) → детерминированный keyword-путь (офлайн, тесты). Анти-гейминг: повтор одной
реплики почти не двигает оппонента. Разбор цитирует реальные ключевые ходы (`views.turning_points`).
